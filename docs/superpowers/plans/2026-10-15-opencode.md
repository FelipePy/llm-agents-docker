# OpenCode no container: plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rodar o OpenCode no container do `llm-agent` do mesmo jeito que o Claude Code e o Codex.

**Architecture:** O OpenCode é instalado pelo npm na mesma imagem, com versão fixada por build arg e registrada em label. O estado dele no host é montado em leitura e escrita. O script `llm-agent` ganha a opção no menu (modo autônomo via `OPENCODE_PERMISSION`), a checagem de atualização e a preservação da versão no rebuild.

**Tech Stack:** Bash, Dockerfile, Docker Compose v2, npm (`opencode-ai`).

**Spec:** `docs/superpowers/specs/2026-10-15-opencode-design.md`

## Global Constraints

- Pacote npm: `opencode-ai`; versão padrão `1.19.1`.
- Label da imagem: `llm-agent.opencode`.
- Variável de versão: `OPENCODE_VERSION`.
- Autoupdate desligado no container: `OPENCODE_DISABLE_AUTOUPDATE: "1"`.
- Modo autônomo só pelo menu: `OPENCODE_PERMISSION='{"*":"allow"}'` (precisa ser um objeto JSON; a string `"allow"` é rejeitada).
- Os 4 mounts são de leitura e escrita e usam `create_host_path: false`: `~/.config/opencode`, `~/.local/share/opencode`, `~/.local/state/opencode` e `~/.cache/opencode`, montados no mesmo caminho relativo em `/home/agent`.
- Comentários e textos sem acento no código (padrão do repositório); README com acentos.
- Docker não está disponível no ambiente do agente: os passos com `docker` rodam no host do usuário.

### Task 2: Script `llm-agent`

**Files:**
- Modify: `llm-agent`

**Interfaces:**
- Consumes: label `llm-agent.opencode` e build arg `OPENCODE_VERSION` (Task 1).
- Produces: `llm-agent opencode [args]`, opção 3 do menu e o array `run_args`, passado ao `compose run`.

- [ ] **Step 1: Ajuda.** No cabeçalho, trocar a primeira linha de descrição e a lista de uso/variáveis:

```bash
# Executa um agente LLM (Codex, Claude Code, OpenCode) em um container que
# enxerga apenas o projeto atual.
#
# Uso:
#   llm-agent                 menu para escolher o agente
#   llm-agent claude [args]   abre o Claude Code
#   llm-agent codex [args]    abre o Codex
#   llm-agent opencode [args] abre o OpenCode
#   llm-agent zsh             abre um shell no container
#   llm-agent --build         (re)constroi a imagem
#
# Variaveis:
#   AGENT_WORKDIR             projeto a montar (padrao: diretorio atual)
#   CODEX_VERSION, CLAUDE_CODE_VERSION, OPENCODE_VERSION
#                             versoes usadas no --build
#                             (padrao: as versoes ja instaladas na imagem)
```

(As linhas de `LLM_AGENT_NO_UPDATE_CHECK` e `LLM_AGENT_DOCKER` não mudam.)

- [ ] **Step 2: `compose()`.** Depois da linha `[ -z "${CODEX_VERSION:-}" ] || ...`, adicionar:

```bash
    [ -z "${OPENCODE_VERSION:-}" ] || printf "OPENCODE_VERSION='%s'\n" "$OPENCODE_VERSION"
```

E trocar a linha `-u CLAUDE_CODE_VERSION -u CODEX_VERSION \` por:

```bash
    -u CLAUDE_CODE_VERSION -u CODEX_VERSION -u OPENCODE_VERSION \
```

- [ ] **Step 3: Menu.** Trocar o bloco do menu por:

```bash
# Sem argumentos: pergunta qual agente abrir. Os agentes rodam em modo
# autonomo, ja que o container limita o que eles conseguem acessar.
# run_args: opcoes extras do "compose run" (ex.: variaveis so desta execucao).
run_args=()
if [ $# -eq 0 ] && [ -t 0 ]; then
  echo "Qual agente abrir em $AGENT_WORKDIR?"
  echo "  1) Claude Code"
  echo "  2) Codex"
  echo "  3) OpenCode"
  echo "  4) Shell (zsh)"
  read -rp "Escolha [1-4]: " choice
  case "$choice" in
    1) set -- claude --dangerously-skip-permissions ;;
    2) set -- codex --dangerously-bypass-approvals-and-sandbox ;;
    # O OpenCode nao tem flag de modo autonomo; libera tudo pela config.
    3) run_args=(-e 'OPENCODE_PERMISSION={"*":"allow"}'); set -- opencode ;;
    4) set -- zsh ;;
    *) echo "llm-agent: opcao invalida: '$choice'" >&2; exit 1 ;;
  esac
fi
```

- [ ] **Step 4: `build_image`.** Depois de `: "${CODEX_VERSION:=$(image_version codex)}"`, adicionar:

```bash
  : "${OPENCODE_VERSION:=$(image_version opencode)}"
```

- [ ] **Step 5: Checagem de atualização.** No `case "${1:-}"` do update check, depois da linha do `codex)`, adicionar:

```bash
    opencode) check_update opencode opencode-ai OPENCODE_VERSION "OpenCode" ;;
```

- [ ] **Step 6: Pastas no host.** Trocar `mkdir -p "$HOME/.codex" "$HOME/.claude"` por:

```bash
mkdir -p "$HOME/.codex" "$HOME/.claude" "$HOME/.config/opencode" \
  "$HOME/.local/share/opencode" "$HOME/.local/state/opencode" "$HOME/.cache/opencode"
```

- [ ] **Step 7: Passar `run_args`.** Trocar a última chamada por:

```bash
  compose "${override_args[@]}" run --rm "${run_args[@]}" agent "$@"
```

- [ ] **Step 8: Sintaxe e ajuda.**

Run: `bash -n llm-agent && ./llm-agent --help | head -12`
Expected: sem erro de sintaxe, e a ajuda mostra `llm-agent opencode [args] abre o OpenCode`.

Se o `shellcheck` estiver disponível: `shellcheck llm-agent`. Não deve aparecer nenhum aviso novo.
